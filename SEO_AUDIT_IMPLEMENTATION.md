# Fekitech SEO Audit and Implementation

Date: 2026-08-04  
Site: https://fekitech.co.uk/  
Project: Vite + React static/SSR prerendered site

## Baseline

- Framework: Vite 6, React 19, static prerender via `src/entry-server.jsx` and `scripts/postbuild.mjs`.
- Rendering strategy: client React app with SSR HTML generated for `prerenderRoutes`.
- Routes: declared in `src/lib/site.js`; runtime routing in `src/App.jsx`.
- Global components: header, footer, chatbot and protected page components in `src/App.jsx`.
- Blog source: `src/blogPosts.js` plus `src/newBlogPosts.js`.
- Service source: `src/serviceData.js` rendered by `src/components/ServicePage.jsx`.
- Metadata/canonical/schema: `src/lib/site.js` and `src/lib/seo.js`.
- Sitemap/robots: generated by `src/lib/seo.js` during `scripts/postbuild.mjs`, output to `dist/` and `public/`.
- Redirects/rewrites/security headers: `vercel.json`.
- Image handling: static files in `public/`, direct `<img>` tags with width/height.
- Existing commands: `npm run build`, `npm run preview`, `npm run seo:check`, `npm run index:chatbot`.

Baseline command results before implementation:

- `npm run build`: passed.
- `npm run seo:check`: passed for 26 public routes.
- `npm test`: failed, missing `test` script.
- `npm run typecheck`: failed, missing `typecheck` script.
- `npm run lint`: failed, missing `lint` script.

## Issues Found

- Blog archive loaded every post on `/blog` and had a JavaScript-only `/blog/all` load-more pattern, which limited crawlable archive structure as the blog grows.
- Vercel rewrites only listed one explicit blog article, creating production risk for other generated blog URLs.
- No crawlable `/blog/page/2` archive despite the need to limit archive pages to 12 cards.
- KPI dashboard articles had overlapping title/H1 language even though they served distinct intent.
- Career-development and training service pages overlapped around career language; the business/team training page needed stronger employer/workforce targeting.
- Service pages had a shared hard-coded `lastModified` date rather than a maintainable per-service date.
- The existing SEO QA script did not test blog pagination, archive card limits, generic blog rewrites or protected-page regression.
- The app bundle grew because long-form content is stored directly in JavaScript data files.
- Vite preview serves clean subpaths as the SPA fallback locally; explicit prerendered files and Vercel rewrites are required to inspect generated static metadata.

## Technical SEO and Performance Notes

- Build output after implementation:
  - CSS: `207.59 kB` raw, `39.63 kB` gzip.
  - Main app JS: `327.56 kB` raw, `95.00 kB` gzip.
  - Motion chunk: `115.93 kB` raw, `45.92 kB` gzip.
- Main JS increased because long-form article content is bundled in source data. A future improvement would move article content to split JSON/MD modules or a content collection.
- Existing CSP is report-only. If changed to enforcing, `img-src` must account for externally hosted Pexels testimonial avatars or those assets should be self-hosted.
- `/admin` is noindexed and API authenticated, but the static login shell is public. Add route-level protection if the login page itself should not be publicly reachable.
- `public/_redirects` remains a Netlify-style SPA fallback and should not be used for the Vercel deployment strategy.
